## Исходный проект

В проекте уже реализованы:

- интерфейс `BaseAnalogClock`;
- класс `AnalogClock`, хранящий время как положение стрелок и признак `AM/PM`;
- интерфейс `BaseDigitalClock`, с которым должен работать клиентский код;
- `ClockFormatter` для форматирования времени;
- `ClockHistory` для хранения истории установленных значений;
- пример клиентского компонента `DigitalClockDisplay`.

## Важное требование

Adapter и Facade решают разные задачи.

- **Adapter** преобразует один интерфейс в другой.
- **Facade** предоставляет более простой интерфейс к подсистеме.

Не следует объединять их в один класс только потому, что оба используются в одной лабораторной работе.

## Описание решения

### Adapter

`DigitalClockAdapter` - переводчик между двумя разными способами работы со временем. Клиент передаёт обычный объект `datetime`, а `AnalogClock` умеет хранить только дату, углы трёх стрелок и значение `AM` или `PM`.

При установке времени адаптер выполняет простые преобразования:

- час умножается на 30 градусов;
- минуты умножаются на 6 градусов;
- секунды умножаются на 6 градусов;
- часы до 12:00 получают значение `AM`, остальные — `PM`.

При чтении времени адаптер выполняет обратные вычисления. Поэтому `AnalogClock` менять не надо, а клиент может работать с ним через привычный интерфейс `BaseDigitalClock`.

### Facade

`ClockFacade` нужен для упрощения работы со всей подсистемой. Внутри него находятся адаптер, форматировщик и история. Клиенту не нужно создавать их по отдельности и помнить, в каком порядке вызывать.

Фасад предоставляет четыре простые операции:

- `set_date_time()` — установить время;
- `get_date_time()` — получить время;
- `get_formatted_date_time()` — получить красивую строку;
- `get_history()` — получить историю изменений.
